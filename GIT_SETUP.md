# Setting Up Git for the Interactive Textbook

A short, safe path to getting this project under version control before we build
further. Everything here runs in `/workspace`.

Git is already installed (2.39.5). I've already created the `.gitignore` for you
(see the safety note in Step 2) — you just run the commands below.

---

## ⚠️ The one rule: never commit `.env`

`/workspace/.env` holds the instructor Anthropic API key. If it ever gets
committed, the key is exposed **and stays in git history even if you delete the
file later** — the only real fix at that point is to rotate (regenerate) the
key. The `.gitignore` I created already excludes `.env`; Step 4 includes a check
to confirm it's actually being ignored before your first commit.

---

## A note on file ownership (do this as the `claude` user)

Every file in `/workspace` is owned by the `claude` user, not `root`. If you run
`git` as `root`, git 2.39.5 will refuse with *"detected dubious ownership"* and
your `.git` directory would end up root-owned while everything else is
`claude`-owned — a mess.

**Simplest fix:** run every git command as `claude`. From your root shell:

```bash
sudo -u claude -H bash    # drop into a claude shell (do this once)
cd /workspace
```

Then run all the steps below in that shell. (Alternatively, just ask me — Claude
Code — to run them; I already operate as the `claude` user, so ownership stays
clean.)

## Step 2 — The `.gitignore` (already created)

`/workspace/.gitignore` is in place. It keeps out:

- **`.env` and any `*.key` / `*.pem`** — secrets (the important one)
- **`build/`** and `*.latexml*.log` — generated by `pipeline/build.sh`, always
  regenerable from source
- **`.venv/`, `__pycache__/`, `node_modules/`** — dependencies/venvs
- **`The_Alchemy_of_Mathematical_Cryptography.zip`** — the ~8 MB original bundle,
  redundant with `textbook_source/`. (Delete that line in `.gitignore` if you'd
  rather track it.)
- **`.claude/settings.local.json`** — local tool settings

What *will* be tracked: `spec.md`, `pipeline/` (the build scripts),
`textbook_source/` (your `.tex` + images — the canonical source), the HELP/HOWTO
docs, and `creature_art_prompts.md`.

## Step 3 — Initialize and make the first commit

```bash
cd /workspace
git init
git add .
git status            # LOOK at this list before committing (see Step 4)
git commit -m "Initial commit: spec, LaTeXML build pipeline, textbook source, docs"
```

---

## Step 4 — Verify before you trust it

Confirm the secret is NOT staged, and see what you committed:

```bash
# Must print nothing. If it prints ".env", STOP — do not push anywhere,
# fix .gitignore, and re-check. (git rm --cached .env to unstage it.)
git ls-files | grep -x ".env" && echo "!! .env IS TRACKED — FIX THIS" || echo "ok: .env is not tracked"

git log --oneline          # your first commit
git ls-files | head -40    # the tracked file list — sanity-check it
```

You now have local version history. **This is enough to keep building safely** —
you can stop here.

---

## Step 5 (optional, later) — Push to GitHub

The spec plans to distribute the project on GitHub eventually (Q9). No rush, but
when you're ready:

**With the GitHub CLI (`gh`)** — easiest:

```bash
gh auth login                                  # one-time
gh repo create alchemy-textbook --private --source=. --remote=origin --push
```

**Or manually** — create an empty repo on github.com first (no README), then:

```bash
git remote add origin git@github.com:<you>/alchemy-textbook.git
git branch -M main
git push -u origin main
```

Notes:
- Start **private**; make it public later once you've confirmed no secrets are in
  history. The `.gitignore` keeps `.env` out, so you're clean as long as Step 4
  passed on every commit.
- The reference implementation being public is a *feature* here (Q9) — just never
  the key.

## Everyday workflow (once set up)

```bash
git status                     # what changed
git add -p                     # stage changes (review each hunk)
git commit -m "message"        # commit
git push                       # (after Step 5) publish

# Try something risky on a branch:
git checkout -b experiment
# ...work...
git checkout main && git merge experiment   # keep it
# or: git checkout main && git branch -D experiment   # throw it away
```

Rule of thumb for this project: commit after each meaningful unit (a spec
revision, a working pipeline change, a chapter edit). Small, frequent commits
make it easy to see what changed and to roll back a bad step.

---

## If a secret ever gets committed anyway

1. **Rotate the key** in the Anthropic console immediately — assume it's
   compromised. Deleting the file or rewriting history is *not* sufficient on its
   own, especially if you already pushed.
2. Put the new key in `.env` (still gitignored).
3. If it was only committed locally and never pushed, you can also scrub history
   (`git filter-repo` / BFG), but rotating the key is the step that actually
   protects you.
